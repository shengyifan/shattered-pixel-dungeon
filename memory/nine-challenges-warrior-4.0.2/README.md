# 战士九挑战：源码研究与实战入口

研究日期：**2026-10-10**。源码基线：`8405ae82f`（`feature/mac-cli`），游戏 **4.0.2 / code 922**，
当前项目接口 **CLI.9.0.3 / protocol 9 / schema 12**。九挑战同时开启的位掩码是 `511`，
但未来实战必须通过当前公开菜单/观察确认所有九项已选、职业为战士，不能拿本文件作为已开启的证据。

用户目标：为之后使用战士开启全部九项挑战通关，系统研究当前源码并把可复用知识保存在项目内。
初始源码研究没有启动游戏、读取个人存档或私有审计、操作现有角色、改动游戏规则。
后续已记录[2026-10-10九挑战实战失败](../2026-10-10-warrior-nine-challenges-retrospective.md)：
战士在第4层饥饿死亡，依据公开响应和源码复盘；没有读取存档或私有审计。
**当前资料包含源码研究与一局失败证据，尚无九挑战通关证明，也不保证任意随机开局必胜。**

**2026-10-11补充研究：** 在第4层失败复盘基础上，以最大化通关机会为目标，新增逐层探索/离层条件、
特殊与隐藏房、分阶段炼金优先级，以及当前CLI玩家信息审计。源码/包仍是4.0.2 / CLI.9.0.3；
本批工作树基线`d04c8f862`，没有改变游戏规则或修复CLI产品行为。

## 证据等级与维护方式

名称优先按当前英文类名/公开道具名定位，中文短称只作阅读辅助。尤其要区分普通**净化药剂 Purity**
与异种**全面净化合剂 Cleansing**：清饥饿/清身上负面的是后者。植物的当前中文名为
**阳春草 Sungrass**、**魔皇草 Mageroyal**，不沿用其他译名来猜物品身份。

- **源码确认**：具体方法的执行路径、公式和保存字段；正文附源码路径与行号。不把文本描述或注释单独当最终实现。
- **隔离验证**：用合成对象/地图或内存序列化验证的有限结论。弹道夹具和保存夹具有各自范围，均不证明完整游戏中战术可重复或最优。
- **战术推导**：从规则导出的有条件建议，例如使用格挡武器弥补护甲削弱、以走位减少集群召集。
- **待实测**：存在代码入口，但行动窗口、UI操作、实际收益或复杂状态组合还未完整验证；不要把它作为必需生存环节。
- **本版实战**：[2026-10-10失败复盘](../2026-10-10-warrior-nine-challenges-retrospective.md)保存4.0.2的一局公开结果。
  3–5次等待等止损预算是保守策略建议，不是原生参数、最优证明或通关保证。
- **历史经验**：[2026-10-08复盘](../2026-10-08-warrior-playthrough-retrospective.md)来自旧游戏3.3.8，
  可沿用证据纪律与失误类型，不直接搬运数值、天赋或当时库存。本目录重新核查4.0.2规则。

后续源码有变动时，应先比较 [来源清单与SHA-256](evidence/source-manifest.json)，再重跑与变动相关的隔离验证。
没有经过验证的旧字段/碰撞/保存结论不得自动升格为新版本事实。源码基线仍保留原提交，不把文档提交SHA混作被研究代码SHA。

后续实玩新增经验应写明：实际游戏版本、挑战开关、公开原始响应定位、操作与资源成本、已确认结果、推断边界。
不将存档、私有audit、隐藏怪物目标、未公开地形或标签映射导入研究库；本目录保存的是公共规则与公开实战证据。
死亡后公开的鉴定与地图仅用于事后复核，不回填行动前的知识，也不成为下一局颜色或路线绑定。

验证范围、运行方法、覆盖数量和仍未完成的端到端验证见 [研究验证记录](evidence/README.md)。
