# spdctl 玩家信息准确性：2026-10-11审查总报告

源码基线 `d04c8f862b2f90418a6375f0b3ffc5c4325d0953`；CLI.9.0.3 / protocol9 / schema12，
游戏4.0.2/code922。该提交与前次游戏/CLI基线`8405ae82f`之间只有资料变更，本次又用实际打包入口确认版本、
帮助文本及相关class一致性。审计包括源码、既有回归、隔离原生对象和正式Python解码器；没有操作现有游戏、
启动个人存档、读取私有audit或改动运行代码。

**不能回答“所有玩家信息都已完整准确展示”。** 主要英雄、背包、地图、状态与文本路径已有较充分覆盖，
但本轮确认了合法魔晶状态触发客户端解码失败、部分图标身份/选中状态遗漏、配方逐材料不足提示遗漏，以及仪式标记的默认可发现性差距。
另发现一个语义校验覆盖不足，并确认声音尚无完整表达路径。以下按根因与证据范围分开记录，不将测试通过等同于全界面等价。

## 1. 如何理解“玩家能掌握的信息”

1. **当前公开事实**：英雄数值、当前已知地图、现有物品假身份、已显示条/计数、真实可见警告和原生控件。
   这些应准确保留，不依赖标签猜测或上一帧内容。
2. **按需检查的信息**：原生必须打开物品/敌人/地格/任务/商店窗口才能读到的详情，CLI通过同样操作读取即可。
   不要求在默认地图提前倾倒所有窗口内容；但当前画面已经提供的识别线索不能无声丢失。
3. **玩家通过来源和规则推断的假设**：例如某谜题在本层补一瓶特定药、某区域保底物品的分布。
   这是决策层推理，不能将推断写成已鉴定瓶名、未见房间位置或隐藏计数。
4. **玩家未知内容**：未揭露地形、敌人精确HP/AI目标/未来随机数、未鉴定等级/诅咒、精确内部饥饿计数。
   这些不应为“完整性”而暴露。当前只输出饥饿阶段不是缺陷。

本轮边界依据：[协议手册](../../docs/cli-help.md)、[客户端契约](../../docs/cli-playthrough-client.md)、
[项目维护skill](../../skills/shattered-pixel-dungeon-cli-release/SKILL.md)。

## 2. 确认问题与修复优先次序

P1表示可能直接阻断正常决策，P2表示有实际信息差异，P3表示健壮性或尚未观察到坏生产值的校验缺口。
这些是本次审查排序，不是已实施修复清单。

根因详情与精确源码行：[16d物品](16d-cli-items-audit.md)、[16b界面/炼金](16b-cli-ui-alchemy-audit.md)、

UI-1/UI-2同属图标拥有者适配不足，不把每一页/每个图鉴类别重复算成不同问题。

**声音边界W-1：** Alarm/Guardian等有视野外仍可触发原生警报音的代码路径，而RuntimeObserver/公开事件没有对应音频语义。
只有SFX开启、非零音量、资源加载并实际播放成功、用户确实可听时，才是GUI相对CLI的额外信息。
本轮仅确认源码可达与缺少管线，没有实际播放音频做端到端复现。后续若支持，只能报告“听见警报”等已审核意义，
不能附带玩家未知道的触发格、隐藏AI目标或怪物身份。具体条件见16a。

## 5. 对后续九挑战实战的具体影响

1. **正式长局前优先修I-01。** 魔晶是正常可获得的附魔，不能保证整局不会遇到；不应以删掉合法glow来继续游戏。
   真遇到DecodeError时保留原始帧与原动作rid/outcome，先确立动作结果，不能重放动作或拿full当绕过。
2. **匿名入口靠打开后确认，不靠固定顺序。** 修复前只能用当帧广告操作逐次进入，读新页面标题/说明确定身份；
   这有额外检查成本，不与GUI识别图标等价。后续修复要避免把常量顺序作为新的隐藏协议。
3. **特殊房线索需要原生检查。** 地图Floor不能证明没有custom图案；对已有公开依据的可疑地格examine。
   不从任务生成代码猜未公开房型或把全部普通格当未知特殊房。
4. **饥饿规划用公开阶段、已吃食物与可靠显示计时的累计证据。** 不为做预算读取内部hunger、存档或私有audit。
   新探索/炼金章节的配额与概率只作为规则知识，绝不是当前局的隐藏物品定位。

## 6. 尚未完成的验收与修复交付边界

本轮尚未把所有真实窗口、全部物品/怪物状态、所有滚动位置、语言、声音、动画、未知身份组合做端到端GUI/CLI差分。
多结果炼金Craft/费用/产物的完整关联、未映射图标fallback、每种神器动态说明仍列候选，不在没有证据时扩大为确认缺陷。

本轮用户要求“看下是否准确展示”，完成的是审计及可复现问题清单，**没有修改CLI行为**。
后续维护应先修已确认根因并补跨语言与真实窗口回归，再按维护skill同步适用的CLI版本/文档、重建实际包并验收。
保留原生战斗/生成/保存规则；不以修观察层为理由改变九挑战难度或开放隐藏信息。
