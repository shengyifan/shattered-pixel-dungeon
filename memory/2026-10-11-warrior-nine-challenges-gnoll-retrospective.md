# 2026-10-11 战士全九挑战复盘：成长豺狼人、持续追击与未兑现的战力

本局在第3层被成长精英豺狼人杀死，未通关。**需要改变的不是最后一击的运气，而是此前的决策链：
初始输出与力量缺口没有补上，带着追兵移动却没有形成断追或清敌终点；为了鉴定和加工制造的寒区又限制了
自己的退路，最后在前方陷阱/寄居蟹、后方两只豺狼人之间失去可承受的退出方案。**

这是同日另一局，与[第4层蝇群死亡](2026-10-11-warrior-nine-challenges-retrospective.md)分开保存。
它也不是[此前饥荒死亡](2026-10-10-warrior-nine-challenges-retrospective.md)的重复：本局无`rest`请求，
公开英雄帧没有`starving`，死亡前仍有一份口粮与170照明。本文区分实耗、源码机制和未验证的战术推导；
没有重放同种子，不能证明换一种选择必胜。

## 1. 证据范围与结局

- 实际握手：CLI.9.0.4 / protocol 9 / game 4.0.2 / code 922 / audit schema 12。
- 复盘源码基线：`cb4ee28e09b9319b08a80ba5098fa17af653d171`。包的`build_id`另见证据manifest，不混同文档提交。

- 最终`t2.487 / s3 / rkd`：`completed`、`phase:ended`、`run_outcome.result:lost`，第3层、2级、经验6/15、
  力量10、0/25HP、金币143；反馈`Gnoll scout killed you...`。
- 全部游戏输入通过同一`spdctl control --machine`连接。复盘只读原始公开传输、控制器记录和源码；
  **本次没有读取个人游戏存档、排行榜存档或私有audit，也没有获得这类额外读取授权。**

[冻结证据与离线校验](evidence/2026-10-11-warrior-nine-challenges-gnoll-loss/README.md)保存488对完整child wire，
以及从`t2.5`开始的414条控制器记录。原JSON字节无损归档，选择字段的关键帧索引不能替代完整观察。
旧坐标、句柄和药色仅用于复核，不是下一局的绑定。

最后一条发送是`t2.487`；死亡后没有新请求，也没有`quit`请求。传输事件随后记录了`EXITED:0`。
因此先前对话的“进程保持打开”不能继续作为已验证现状；只能确认停止输入及后续记录到正常退出，不能从这里猜测退出原因。
死亡帧自动揭示的装备等级/诅咒不回填生前知识；例如鞭子在`t2.486`仍是等级/诅咒未知，不能用死后鉴定解释当时选择。

## 3. 首层：操作成功的奖励，也要区分能否立即投入战斗

首层做对了多次门口偷袭、投石削血及回收。满血时的两次直觉判断分别排除jade/charcoal为力量；
这没有证明剩余magenta一定是力量。之后试饮实际确认magenta为隐身、jade为加速，均没有直接掉血。
药色只属于本局；后来的charcoal投掷只显示无害溅开，未确定类型。

哨兵房使用了已确认的加速，按公开地形绕雕像，到非危险地板开箱，再沿原路返回，实际无伤：
`t2.209`加速20、25HP；`t2.219`取得黏稠鳞甲；`t2.222`回到房门，仍25HP、加速10。
随后利用剩余加速兑现已有金钥匙对应的锁箱，`t2.228`取得鞭子。
从`t2.194`到228，照明163→131，共32，HP一直25；这包含试药、哨兵房及锁箱，不能全部算“贪箱浪费”。

但两件奖励的**当时公开需求估计**是鳞甲16、鞭14，英雄力量只有10；鳞甲已知无咒，鞭等级/诅咒未知。
没有盲穿是正确的，收到装备也没有补上即时输出。首层满血离开并不等于第二层的战力准备完成。
[Weapon力量惩罚](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/items/weapon/Weapon.java)、
[MeleeWeapon力量需求](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/items/weapon/melee/MeleeWeapon.java)
支持分别核查伤害、命中、攻速与当前力量，不能只看物品阶数。

**下次改进：** 每次奖励落袋后立即更新“可立即装备/施放”“需要的已知力量或升级”“未来候选”三项。
追踪已见药卷与能够兑现的目标，但不把生成配额当作已知位置，也不宣称本局必有某张漏拿升级卷。
昂贵回收取得超重装备后，不继续以“已经升级战力”为前提进入下一层。

## 4. 第二层：绕过单只敌人，不等于结束整场追击

### 4.1 对巨型鼠的第一次投石，交换代价已经不合算

`t2.244`门口25HP，看到巨型鼠；`t2.248`远投只造成1伤，英雄被隔格打4，25→21，投石同时损坏。
巨型词缀的高减伤和额外近战距离已公开，不能沿用普通鼠“远投是免费削血”的经验。
随后停止继续投射换血是合理纠正，但这一回合已付出的HP和弹药不能在计划中忽略。

[ChampionEnemy.Giant](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/actors/buffs/ChampionEnemy.java)
规定额外射程和两步可达检查；“不能过窄门”不等于“门另一侧一格就安全”。
其攻击路径还受其他角色占位影响，必须按同帧地形与所有实体核查，不能只算切比雪夫距离。

### 4.2 回环只维持了距离，补给和战斗能力都没有兑现

豺狼人、蛇与巨鼠持续压迫路线，西门又被普通鼠堵住。杀门鼠后绕过桥上豺狼确实成功，
但不是已证明安全的通路：未知charcoal在`t2.267`投出只产生无害溅开，没有提供控制；
后续能穿过是敌人移动让出格子后的新机会，不能归功于药剂，也不能把旧“必须杀西豺狼”的推断当定论。

`t2.244`的25HP/光104，到`t2.293`退回1层时为10HP/光66，
照明相差38且经验仅增加一只挡门普通鼠的1点。若干卷轴、药剂和钥匙虽已见，却因队列追击无法安全拾取。
问题是追击状态持续跨房，而非每一步移动都错误。

**下次改进：** 逃跑必须指定可验证终点：真正断视线并拉开距离、缩减队列、跨层隔离、已知控制或完成必要穿越。
同速移动很多步仍邻接一只敌人时，不能将新的未知房间不断追加为“退路”。在尚有血量/工具时就比较
一场可承担的门口战斗、已见关键资源和退层方案；不能等最后所有动作都只是继续躲避。
该规则不保证当时存在无伤替代路线，也不要求为了经验清全层。

### 4.3 有限恢复遵守了预算，却没有解决重新进入后的风险

`t2.293→311`在已清过的1层用23个照明单位换取10→13HP，并在同一预算内回收74金币；
其中`t2.294`一次、`t2.301–311`十一回，共12次逐帧单wait；余下为往返及拾取，没有长rest或进食。
到13HP即停止，属于真实执行的硬预算。

但`t2.314`回2层仍看到入口追兵，`t2.316`又受4伤（13→9），`t2.321`受3伤至6，
后续靠绕行和闪避才到出口。局部+3HP没有覆盖重新穿门/绕精英的负担，也没有改变输出、工具或队列。
这不能证明“多恢复一定成功”，更不能因为一次有限恢复效果差就禁止所有退层恢复。
[RegularLevel.mobLimit](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/levels/RegularLevel.java)、
[Regeneration](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/actors/buffs/Regeneration.java)、
[Hero休息与移动](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/actors/hero/Hero.java)
提供的只是条件：首层普通补怪限制、基础恢复和原生休息终止规则；hungry本身不是长rest停止保证。

**下次改进：** 恢复方案同时写“回多少HP、花多少粮光、再次进入后前几步会遇到谁、需要承受多少攻击”。
恢复目标不能只由剩余火把倒推一个小数字；必须覆盖一个可执行的重新进入方案。
无法覆盖时就承认这一方案没有修复主要缺口，不能把恢复后的状态包装成完成整备。

## 5. 第三层：把加工和回收成本放进控制预算

### 5.1 安全进食值得保留，不必只等丰盛阈值

本局唯一一次进食是`t2.389`：口粮2→1，HP11→11，照明232→229，hungry消失，没有受到攻击。
这是正常三时间进食，补100营养，没有丰盛的4HP直接治疗。25最大HP时丰盛1需当前HP≤8，
不能主动受伤凑阈值；也不能一直保留食物，直到再次进入无法停下来的追击。
[Food](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/items/food/Food.java)、
[Talent.onFoodEaten](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/actors/hero/Talent.java)。

营养延长后续自然恢复窗口，但之后的HP增长还受原本营养和实际时间影响，不把全部回血机械归给这餐。
死亡前留有一餐，只能说明最终位置没有安全吃完的机会，不等于食物本身不可用或应在被夹击时强吃。

### 5.2 试投即时安全，不代表生成的环境对路线安全

`t2.416`英雄1084、13HP、光207，持两瓶未知turquoise。`t2.419`将一瓶投到已走过的1126，
原生识别为冰霜，自己无伤，保留一瓶。远投辨识有实际收益；错误在于后续没有把寒区占据的通路作为持续成本。

`t2.422`把生肉投到1127，公开实体确认变成冻肉；英雄走到1128，`t2.425`单wait等寒区消散。
随后想利用这段时间去取已见金币，原旅行`t2.426`目标为1038，实际只到1083；观察428首次看到成长豺狼人900。
其原回执`t2.427`为`COMPLETED`、`save:[]`，不是`INTERRUPTED`，也没有发送`cancel`。
金币计划随即取消，没有实际取得金币，也没有在第二瓶冰霜生效后继续捡金币；不能照抄上一局“控制后追加锁箱支线”的叙述。

真正的问题是：**加工与等候发生在回环通路上，寒区暂时封住了西侧撤离路线，安全投掷位置没有附带安全回收/脱险证明。**
`t2.429–431`被迫退到暖格并等待；`t2.437`又花掉最后一瓶冰霜，为绕西腿离开争取时间。
从`t2.416`到437，照明207→197、金钱未增加、冻肉未入包，两瓶冰霜已耗尽。
不能证明不做加工就绝不会遇到这只敌人，但这次增加的环境限制与未兑现的回收成本是真实的。

[PotionOfFrost](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/items/potions/PotionOfFrost.java)、
[Freezing](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/actors/blobs/Freezing.java)、
[Heap.freeze](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/items/Heap.java)
解释药效、持续冷区与食物转化。**冻肉生成不等于已获得一份食物**；未安全拾回时，仍是地面资产。

### 5.3 寒冷已经生效，但追击没有终止

`t2.437`明确反馈`Chilled`，随后成长豺狼人仍沿1038→1083→1128→1127接近。
不能将“投中冰霜”写成“敌人被冻结”，也不能按固定冻结时长安排拾取。
之后实际放弃冻肉/金币，只撤离，是有效收敛；`t2.443`北侧又见普通豺狼人，
绕过它时一次闪避、一次由新触发纹章盾吸收4伤，英雄最终15HP+1盾通过北侧横道（`t2.452`）。

然而两个敌人仍跟在后面。`t2.461`穿过东门、`t2.465`到新走廊时，
没有完成断追、消灭或跨层隔离，仅延长了这场遭遇。控制后不追加支线已执行，但**必须验证脱离是否真的完成**。

## 6. 最后狭道：杀掉挡路怪之后，移动本身仍可能致死

`t2.474`前方1050新发现寒冷陷阱，1005门被寄居蟹占据；上下是已知墙。
陷阱到这一帧才被动发现，不能回填为此前已经知道的障碍；不能要求当时预知隐藏陷阱的位置。
后方普通豺狼人1048与成长豺狼人形成夹击。寄居蟹是25HP、2–6减伤、速度1的变体，没有可利用的“缩壳后让路”。
未触发的可见陷阱会被普通非飞行、非Amok怪物避开，暂时隔开寄居蟹；主动触发会把英雄也放进寒区。

## 7. 下一局的执行门槛与协作教训

以下为本局证据支持的保守策略，尚未验证最优胜率，也不把缺少资源等同于必须盲目清图：

1. **成长资源只认已兑现。** 离层审计列当前力量、有效武器/杖、经验与天赋、已知控制；超重鞭/鳞甲属于未来候选。
   记录已见未取药卷的具体回收条件，别让“活着到下一层”掩盖仍是初始输出的事实。
2. **退路计划至少覆盖两个边界。** 不只验证眼前格可走，还要核过门后能否避开攻击、是否单出口、下一段何处停。
   有追兵时不把未知门后的空间承诺为安全；新敌封路立即重新评估整场队列。
3. **恢复必须覆盖再次进入的代价。** HP、食物、照明与敌人占位一起预算；明确恢复后的首段路线，不只设一个小回血数字。
4. **可选加工必须保留替代退路。** 持续气/火/寒区的生成、等待、回收和遇敌退出都计入成本。
   缺少替代路线时，不为可选试药或加工在当前唯一通路制造寒区；用于控制敌人或必要突破时，另行预算完整退出路线。
   已出现威胁时允许放弃地面成果，不能为证明前面的投入有用再耗最后控制。
5. **只按已观察到的控制强度行动。** `Chilled`不能当`Frozen`；作用于敌人也不等于它不会再追。
   控制后立即验证目标是否完成，临时延长距离不能自动升级为脱险。
6. **食物与投武按当前可用量计算。** 安全hungry窗口可以为营养吃饭，不必等低血；三时间进食需真实窗口。
   地上投石不是手持弹药，UI中的套装耐久也不是可以连续发射的次数；必要时看当前物品详情。
7. **最坏预算包含退出那一击。** 纳入所有可攻击者的保守伤害，不把上一击低伤、闪避或暂时护盾预支到下一步。
   已被逼到赌博时如实说明风险，不能声称“清了挡路怪就安全”。

本局11次`STALE_STATE`都先通过控制器`settle`确认原请求`REJECTED`，再取新state作新决定。
这些是服务器拒绝，不是解码失败，也没有证据把死亡归给它们；本次不诊断或修改其原因。
公开归档能核对请求唯一性与原结果，不能把后来的fresh state伪装成旧动作回复。

协作中的当前公开帧必须和实际收完的响应ID一起交接。一次协调ACK曾在仅收到终端回显时误指向旧`t2.32`，
后暂停转发、只接收原`t2.33`，没有重发攻击；这是对话中记录的协调失误，wire证据可核对该攻击仅发送一次，
不能从wire单独还原本地ACK事件。未来保持单一写入者，ACK只在完整响应收取及解码后更新；
子代理不可访问根的执行会话是工具隔离，不应另启游戏来“恢复”。减少重复源码读取和多轮文件轮询，
但不以裁剪完整公共地图/描述或混用旧帧来缩短决策过程。
