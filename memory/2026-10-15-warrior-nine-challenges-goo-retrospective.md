## 3. 首领战的可复用成功窗口

### 3.1 双向硬墙校验确实躲开了蓄力，但只证明对应的一步

本局公开记录有6次新的`!!!`／pumping蓄力提示，随后均移动脱离，未见蓄力命中。
例如`t2.1046 → 1047`、`1051 → 1052`、`1060 → 1061`、`1068 → 1069`、
`1205 → 1206`、`1210 → 1211`。取消结论结合实际追近动作及后续观察，不能仅凭滴状效果淡出。

[Goo.canAttack](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/actors/mobs/Goo.java#L142)
要求距离≤2且两个方向的硬墙弹道都成立；高草和普通门的软阻挡不够。
本局验证的转角只对那一对英雄／Goo位置有效；敌人追到下一格后必须重新计算。

**改进点：** 预先检查“攻击位→躲蓄力位→下一行动位”三段。若第二个位置没有下一步安全出口，
需要在开始交换前就给出可承受的普通反击、可用控制或收尾保证；不能到窄口才发现只剩一次危险横移。

### 3.2 偏点冲击、电击回充与苦无形成了本局最强的一段输出

西侧门口的历史配对为英雄1032、Goo1066，瞄1067：射线先撞Goo，但后续方向使其向东退入干地；
英雄西北第一推格是硬墙，实际未自推。`t2.1080、1086、1097、1101`均使用这个已核对的窗口，
回复中的Goo通常已在其自身动作后回到1067，不能把回包位置直接当最远击退落点。
其收益是让Goo从干地重新接近，避免边打边让它踩水恢复。

`t2.1089`把电击石投向已核验的1134，范围覆盖Goo而不覆盖英雄；英雄16HP不变，Goo出现Paralysed。
[电击石](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/items/stones/StoneOfShock.java#L48)
无伤害、只短麻痹，按命中角色数即时给法杖补电；它不是“保证连砍几刀”。
此前提出的1133瞄点会撞墙，已在执行前排除，不能当作实际消耗失败。

三枚苦无在`t2.1083、1092、1095`造成11、15、14伤害，后两次有公开偷袭图标；
其中第二次还兑现了激怒加成。未知苦无的预计STR13不能证明实际超重或合力，
这三次成功也不把实际等级倒推成已鉴定。下次仍要按可能超重时的1.2基础耗时预算额外敌方动作。

**首领战伤害账本：** 19次近战尝试，16次命中共126伤害、3次被闪避；投石4；苦无40；冲击波17，
合计187点公开见证伤害。初始120HP到最终26HP，按`120 + 回补 − 187 = 26`得到净回补93。
这是端点与伤害账本推导，**不是逐次观察到93点水疗，更不是读取隐藏回血计数**。

## 5. 恢复额度会负债：不是等得不够久

[LockedFloor](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/actors/buffs/LockedFloor.java#L31)
的核心规则是：

```text
Badder Bosses初始 left = 20
自然时间：只有 left >= 1 才减1；低于1时不继续自然减，也不自行回升
Goo伤害入口：left = min(left + dmg, 50)
Goo水疗：left -= healInc             # 没有下界，可以为负
普通被动恢复开启条件：left >= 1
```

伤害入口加的是传入`dmg`，不应泛化为所有情况下的最终HP净差。
例如`left=-40`后打27只到−13；这是公式示例，**本局没有读取或测量确切left值**。
本文对“曾出现负余额”的判断来自公开端点与源码的定性推导：`t2.1103→1190`没有新增对Goo伤害记录，
Goo净回补77，而预算上限仅50；水疗足以将预算扣到零以下。不能由此补造每次离视野水疗或精确余额。
本局后段纹章冷却停在107、杖0/3未动；后来虽再次造成伤害，也没有观察到普通恢复重启。
不能再说“打一刀就能恢复充能”或“水疗只抵销那几滴血”。

| 受影响的普通恢复 | 必须保留的例外 |
| --- | --- |
| [自然回血／血杯加速](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/actors/buffs/Regeneration.java#L56) | 丰盛即时治疗不是这条路径；血杯外部充能回血也另有条件 |
| [法杖常规回充](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/items/wands/Wand.java#L828) | Recharging额外项与`gainCharge`即时回电另算，电击石仍可有效 |
| [钥匙自然回充](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/items/artifacts/SkeletonKey.java#L431) | 外部`charge`路径不同，不能一概称所有神器充能失效 |
| [纹章正冷却倒计时](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/items/BrokenSeal.java#L323) | 已有盾仍可吸收；就绪盾的合格伤害触发不由`regenOn`统一关闭 |

此外，Goo水疗先于通用麻痹AI分支；电击暂停攻击／移动不保证暂停水疗。
锁层暂停原生饥饿增长，但照明仍耗时，不能把绕行当零成本。

## 6. 最后一段：躲过蓄力，仍死于退出时的普通攻击

后段先在干地重新打出27伤害，英雄22→12；之后通过走位及门口偷袭继续压血。
`t2.1205`偷袭8后Goo蓄力，`1206`绕硬墙成功；`1208`一次普通攻击被闪避，
`1209`下一次普通攻击实际0伤。这些随机结果不能变成后续伤害上限。

`t2.1210`再打12，Goo25/120并蓄力；`1211`南移553，Goo追到520，蓄力取消。
`t2.1212 / r896`重新观察确认英雄仍12HP、无盾，Goo25HP在520，杖0/3、钥匙1/4，仍有1口粮。
最终`t2.1213`从553向西移动到552，**与520的Goo仍对角相邻**，
受到11物理伤害与首次1点污泥伤害，0HP结束；同帧Goo为26/120。

这是明确的执行风险：下半血Goo普通攻击可达1–12，成功攻击还有1/3附污泥，
[Ooze.act](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/actors/buffs/Ooze.java#L91)在5层可先造成1伤再判断水洗。
12HP无盾不能把相邻穿门计为可靠撤退；抗魔布甲的刻印也不额外抵抗Goo或Ooze。
到553后选择已经受限，因此应更早拒绝“只有第一步安全、后续必须挨打”的战斗位，
而不是把最后死亡全部归为运气，也不虚构当时存在一条无伤出口。

最后一餐留在包中不等于有可立即支取的6HP。
[Food](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/items/food/Food.java#L70)与
[Hearty Meal](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/actors/hero/Talent.java#L587)
确认HT40时HP≤13可即时回6，但普通速度、无铁胃仍须支付3时间；慢速／寒冷等另修正。
不能为触发阈值主动挨打，也不能把“先到18HP”当作能承受这段全部敌方动作的证明。

## 7. 信息与协作：保留正确做法，也记录执行前纠正

  再`t2.1050`／`1055`获取新帧并重新决定。没有重放不明结果，没有观察解码失败。

  它们与残留效果变化有时间关联，但本次没有隔离复现，不宣称已证实CLI根因或已修复。
- 顾问曾将`boss_warning:true`误判为正在蓄力；该误判在执行前被已有动作和新反馈纠正，未据此改变行动。
  [BossHealthBar](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/ui/BossHealthBar.java#L65)导出原生警告显示，
  [Goo半血切换](../core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/actors/mobs/Goo.java#L262)控制其狂暴警示。
  对Goo不能把这项常驻旗标单独当蓄力；必须结合新的pumping／`!!!`、当前效果和已发生动作。
- 原始传输始终完整保留并使用正式decoder；但部分常规帧的模型显示过滤了`ui.nodes`，
  使本来已提供的Boss精确文字没有持续呈现。**完整解码不等于完整展示。** 下次保留语义subject、
  关联的状态文字与操作约束，不把显示层裁剪说成游戏本身缺信息。
- 精确HP只使用同帧`status.subject → entities[index]`明确绑定可见Goo的文字。
  锁门后的未绑定面板仍显示1/120，不能用来补造隐藏实时HP；无文字时保留血条估计，不换算成精确值。
- 修改瞄点避免撞墙、苦无可能超重、荒芜下种子不生根等属于**执行前的核验／纠正**，
  不写成已经浪费了相应道具。无即兴投掷时，盲草种子不自动提供失明；不能凭物品名补一个不存在的控制。

## 8. 下一局的执行卡

1. **继续兑现即战力。** 保留早用力量／升级、主动用钥匙／法杖／投武、借明确治疗井强化、
   出口前放弃剩余队列的做法；每次取得奖励后重新列当前可用和未来候选。
2. **首领前看组合，不只看满血。** 当前武器／力量、可靠充能、即时伤害、主动补电、
   吃饭窗口、至少两步退出和照明分别核验。未知杖电量、未回收投武和超重装备不计入保证储备。
3. **首领干地与恢复额度一起管。** 不设计靠Goo水疗换时间的回血／回电循环。
   看到冷却／充能停滞，停止承诺自然恢复；伤害只有偿还负债后才可能重新开启它。
4. **压到残血就重算整场收尾。** 是否能必中收尾、剩余控制是否够兑现击杀、
   隔离后的重新接战会不会让敌人回血，比“先把自己加几滴血”更完整。
   不因此无条件贪刀，所有替代方案仍保留命中、伤害与时序的不确定性。
5. **每个转角审两种伤害。** 一步能躲蓄力不保证下一步不挨普通攻击；
   普通上限、Ooze、真实盾和出口占位都纳入。之前dodged或0伤不能预支给下一步。
6. **控制需要明确兑现点。** 偏点冲击核实际射线、敌我受推与落点；Shock核自晕范围、
   净补电和后续攻击窗口。不要把一次短麻痹当多次必中输出。
7. **搜寻与引怪分开。** 可见不等于敌人已发现英雄；未确认跟随时不继续承诺整条诱敌路线。
   分段搜寻有终点和照明上限，重新见到后立即按当前HP、位置与发现状态改计划。
8. **停止政策优先。** 按准确原rid收敛活动；死亡或不可恢复异常后停止输入和查询。
   战术止损意味着改计划，不授权退出、重开或再试一局。
