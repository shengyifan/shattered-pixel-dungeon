# Project working agreements

- Read `docs/cli-help.md` before operating or changing `spdctl`. It is the authoritative English protocol manual and the bundled `--help` source. Keep this file concise; put detailed schemas and validation results in `docs/`.
- Use CLI.8.0.0, protocol 8 and the currently advertised capabilities. New default profiles use the independent CLI v8 directory and schema 11; reject older or ambiguous nonempty profiles before writes, without migration or deletion.
- Keep CLI requests, responses, help, diagnostics and test output English. The ordinary game GUI may remain Simplified Chinese and windowed.
- Prefer the packaged `spdctl control --machine` controller during gameplay; it owns one `run --machine` child and its serial NDJSON connection. Direct clients must likewise retain one process. Do not read personal game saves or private audit state to choose actions. Isolated, explicitly marked test fixtures are separate from gameplay evidence.
- Normal controller terminal/PTY startup needs no output-file workaround. Its child stderr is an independent pipe with separate best-effort forwarding; keep caller stdout/stderr separate for NDJSON parsing. If deliberately merged, diagnostic text may mix on the terminal while child raw traces stay separate. Local `CONTROLLER_*` diagnostics are not game replies or evidence of action completion.
- Controller actions require the exact displayed `rev`; it supplies scope/version/fresh short request IDs. Expose initial `in_progress`, then use local `settle` or the advertised cancel binding. Never silently rebind an old decision to an unobserved revision.
- With `control`, finish pending actions through local `settle`; manual `req/state` queries do not clear its pending-action bookkeeping. Use `settle.observation` or `controller:"response"`'s nested `response` as the current frame, with that frame's own `s/rev`. Preserve `outcome`, errors and `late_responses` separately; wrapper scope and late replies are not new live bindings.
- Direct clients use the handshake's `request_prefix` plus a fresh decimal counter (ASCII 0-9 only) allocated before sending; failed requests also consume IDs. Do not reuse the long bootstrap ID prefix after discovery or truncate server handles. Opaque profile-local handle prefixes keep their advertised spelling.
- Send one request with a fresh ID, receive and parse its entire response through the newline, then present selected fields to the model. Preserve all original transport bytes independently of display limits.
- A successful synchronous action reply is already the current observation. Do not add an unconditional `state` query after every action.
- After `in_progress`, the controller's `settle` (or a direct client's receipt loop) inspects the original request's small `req` receipt. On `COMPLETED`, `AWAITING_INPUT` or `INTERRUPTED`, obtain one fresh live `state`; do not fetch historical `reply` on the normal successful path.
- If the initial finite operation was `resolving`/`cancelling`, discover the current scope with `info` after its successful terminal receipt before reading state. Preserve any discovery failure. Ordinary `continuous_activity` needs no extra discovery.
- Keep the original action outcome and its save receipts separate from the current observation. A completed state query does not prove the previous action succeeded or saved.
- Historical `raw/reply/before/after` are for explicit diagnosis and verification. Never let a historical revision replace the current live `s/rev`, or invent an original wire response from a fresh state.
- On `REJECTED`, `UNKNOWN`, response loss, parsing/display failure or timeout, preserve the original ID and establish its outcome before any further decision. Never replay a pending, completed or uncertain action. Follow the user's stated stopping policy.
- Retain interruptible travel/rest observations and cancellation. After successful `quit`, wait for process exit; do not send another state query.
- Decode every default observation independently. Omitted schema defaults are not deltas; item and control locators are current bindings, not permanent identities. Inspect the original UI or request full detail when needed.
- Expand each observation's own action, inventory and UI node templates, item labels, entity/effect dictionaries, uniform row visibility and scoped defaults. Missing, null, false and zero retain their documented knowledge meanings. Short handles are profile-local and remain opaque; never truncate or invent them.
- Actions, inventory and UI nodes may mix template rows and expanded objects in every view, including full/src. Expand `act_templates` and `inv_templates`, restore applicable activity/cancel `rev/rid` bindings before copying referenced operations, and expand entity/effect dictionaries and scoped base facts. Then expand `ui.node_templates`, resolve ordered `ops` and item `label` references, and validate semantic `subject` references against this frame's complete hero/inventory/entities/buffs; floor item bindings can come from `entities[].item`. Apply save-scope and remaining defaults against that response only. Preserve protected records and diagnostic paths. Absent/null/empty `ops` does not advertise an action; boolean/float indexes, ambiguous item bindings and missing subjects are decoding errors. Frozen before/after snapshots own separate tables and bindings; raw/reply and source ASTs remain opaque.
- A node may have no `text` or `label` while its advertised operation carries the useful `label`. Read resolved `ops`, explicit subject facts and independent node text together; preserve textless controls and do not infer executability from labels or icons.
- A decoding failure preserves the failed wire response's identity, which may be a state-query ID rather than the original action ID. Keep the original action `rid`, outcome and request from the controller wrapper separately, together with raw transport bytes. Establish the action outcome before requesting fresh detail; never guess missing values or treat full/src as an uncompressed bypass.
- Preserve semantic `inv[].shown` and `buffs[].shown` counts, strength estimates, progress and flags; `health_estimate.samples` bars; `hero.turn_progress`; `ui.feedback`; hazard descriptions; dynamic operations and public world cues. Preserve source-bound `shown.status_kind:"quantity"` and Warrior Shield `shown.counter_kind`/`shown.progress_kind` (`shield` or `cooldown`); equal numeric text does not prove equal meaning. State `ui.nodes[].subject` is an explicit same-frame hero/item/buff/entity reference, never a label guess. Standalone `actions` omits those tables and uses direct `subject_data`, or null plus `unresolved_subject` partial diagnostics. Do not use ad hoc label whitelists, unmarked map crops or blanket `desc` removal to save tokens. Display each response with its own body and identity, never a new header paired with an older cached body.
- All new play/full/src observations, events and frozen snapshots carry semantic gameplay facts, without atlas/frame/transform/RGB, generic particle histograms or screen effects. Reviewed `GameplayBurst` kinds can report actual visible contributor `count` with `basis:"observed_particles"`; the special `sacrificial_flames` density count remains public. Quantity-only history for counted kinds is explicitly sampled at 250 ms, while discrete changes are immediate. World cues use public source/FOV scope independently of camera, viewport and UI occlusion; they must not reveal hidden AI or timers. Full/src add explicit defaults or public provenance, not ordinary rendering detail. Raw/reply history stays immutable.
- Return the complete known floor on each observation, including explored cells outside the window or behind UI. Live enemies and cues remain constrained by public FOV; reviewed static terrain indicators can retain the native display's visited/mapped scope. Meaningful warnings/states participate in revision validation; completed-action feedback and decorative refreshes do not. `electricity_flow` animation is not the stable electrical danger map (`map.env`) and does not alone invalidate an intent. Never derive or replace a revision from visual/event changes.
- Response compaction must be reversible for public observation content: retain item descriptions, all talent entries, retained semantic node identities/order/parents, public text or its explicit owner/feedback representation, and every advertised operation constraint. Redundant passive text/empty placeholders may be coalesced only when public facts survive; protected origins and diagnostics always survive. Full source ASTs remain explicitly available through `src`.
- Expose an interruptible initial response before waiting for its completion. The independent SEND and RECV + ERROR Terminal windows are passive viewers; opening, closing or reopening them is not a game operation and must not stop recording.
- Raw transport records contain exact child wire bytes, not local controller intents/wrappers. Only numbered SEND/RECV heading lines are bold bright cyan; both directions use the same color. Payloads, ERROR and other viewer text remain normal weight, and ANSI styling never enters recorded bytes.
- Keep personal profiles untouched during implementation and regression testing. Use new isolated profiles, and report fixture outcomes separately from real playthrough progress.
- After verified changes, synchronize CLI/protocol/schema versions, launcher, build catalog, help and changelog as applicable; rebuild and verify the actual packaged executable.
- Make a scoped local GPG-signed commit after validation, check `git diff --cached --check`, and verify the signature and worktree. Push, tags and publication require a separate user request.
