# CLI.4.0.1：独立 Terminal 查看器显式启用彩色

2026-09-14，基于 `c9b222532` 修复独立查看窗口依赖自动颜色检测的问题。CLI 升为 4.0.1，协议 4、审计 schema 7、基础游戏 3.3.8 均不变。

同日后续按用户要求清理了此前全部 build 产物及实战故障 JSON。本文保留修复时的验证结论，旧 build 输出和验证附件已清理；当前包的重建结果见 [CLI.4.0.1 清理重建记录](../cli-rebuild-4.0.1-20260914.md)。

## 确认的行为与现场边界

CLI.4.0.0 的 ANSI 上色器正常。对已结束的公开测试记录，包内 `trace view --color always` 产生彩色序列；去掉 SGR 后正文与 `--color never` 完全一致。

自动打开及 `trace open` 使用的临时脚本，与保存在记录目录中的 `open-viewer.command`，此前都只调用 `trace view --session ...`。默认 auto 仅在 stdout 为 TTY、TERM 不是 dumb、NO_COLOR 不存在时启用颜色；NO_COLOR 为空字符串也会禁色。

本次调用端环境为 `TERM=dumb`、`NO_COLOR=1`，但没有仍在运行的独立查看器可核对其环境。`open -a Terminal` 经 LaunchServices 与终端 shell 启动，不能仅凭调用端环境就断言用户此前窗口也继承了这些值。本轮确认的是可复现的禁色路径和专用窗口的启动策略缺口，不冒称已目测用户原窗口。

## 修复

两个可信脚本生成器都显式执行：

```text
spdctl trace view --color always --session <session>
```

自动打开、`trace open` 及新生成的永久重开脚本统一请求彩色。直接运行 `trace view` 的 auto/always/never 语义不变；没有修改终端设置，也没有改变游戏输入、机器 JSON 或原始记录。

旧记录中的脚本保留原参数。需要重新打开旧记录时，使用新包的 `trace open --session ...`，它会用当前可信 executable 生成新脚本，不执行日志目录内可能被改写的脚本。旧窗口已经输出的文本不会自动重新着色。
