# CLI.6.1.0: readable controls and lossless public response compaction

## Evidence and scope

The completed Warrior run reached depth 9 under CLI.6.0.1. Its public transport
contained six definite game-request rejections: three old revisions, a `select`
sent to a click-only button, a packed node shape index sent as `ctl`, and movement
while a chasm confirmation window was open. Controller-local field mistakes and
missing `settle` calls were separate from those six wire rejections. A caller-side
JavaScript exception followed an unchecked error response. Those are client
handling failures, not evidence of a broken revision or execution boundary.

Three wand targeting warnings were native first-step wall collisions: the actual
target differed from the hero, but Ballistica returned the hero cell as the
collision position. The wand used the same message for both cases. The final
depth-9 no-op targets were walls; `completed` did not mean the hero moved. JVM
Unsafe deprecation warnings appeared in the viewer's stderr/ERROR channel and
were not action failures.

Diagnosis and implementation use source, public transport and isolated fixtures.
Personal game saves and private audit databases are not inspected or modified.
This batch does not resume the game or claim a completed playthrough.

## Readability gap versus lossy reduction

The Stone of Intuition's guess buttons had no text or hover label at the native UI
layer. Both play and full therefore exposed unnamed clickable icons. This was
not caused by play compaction. Native localized accessible labels now expose the
already visible candidate type through the existing text-provenance pipeline.
Selecting a candidate remains separate from committing a guess.

The broader audit did find lossy reduction elsewhere:

| Previous reduction | Required corrected behavior |
| --- | --- |
| Remove ordinary inventory and floor-item descriptions in play | Retain all captured public descriptions. |
| Retain only invested talents | Retain zero-point entries, names and tiers too. |
| Remove action parameters, arguments, modes or units even in full | Preserve all advertised constraints and unknown extra fields. |
| Delete empty UI nodes and passive duplicate text | Preserve node count, order, identities, hierarchy and text. |
| Replace captured child text with semantic display fields | Add semantic bindings/display fields without deleting the source nodes. |
| Move node-bound operations out of the global list | Retain the complete original `acts` order; node `ops` is only a convenience copy. |
| Discard coverage or extra presentation/diagnostic fields | Preserve public coverage, nulls and diagnostic details; reject conflicting aliases explicitly. |
| Permit node/ID deletion in benchmark normalization | Compare retained public content strictly; a smaller output is not proof of equivalence. |

Reversible dictionary references, row maps, same-frame exact labels and documented
scoped defaults remain. Each frame must decode independently, preserving unknown
map gaps, distinct terrain, null/false/zero knowledge, render measurements,
operation metadata and protected diagnostics. Full source ASTs still require
`src:true`; this is an explicit retrieval boundary rather than deletion of public
observation content. No source or clipped text is reconstructed from hidden data.

## Input and result handling

The packaged controller rejects malformed `ctl`/`loc`, missing directions and
non-integer map cells before dispatch. `id` remains controller-owned. Static
validation does not choose a target or replace engine availability checks.

The reusable `desktop-control/client/spdctl_client.py` helper decodes the current frame's dictionaries and validates
an explicitly supplied intent against its revision and advertised operations.
It keeps errors, original outcome, fresh observation, discovery and late replies
separate. It performs no game I/O, automatic action replay or revision substitution.
An error response has no assumed normal `data`; packed arrays are decoded from
`node_shapes`, never indexed as if their first value were a control ID.

Strict stale rejection, explicit `settle`, unknown-outcome holds, raw transport
recording and the original game's turn/target rules remain in force. A wand whose
first step is blocked now reports a blocked path rather than self-targeting, and
still spends no charge on that branch. After any input, clients must read the
returned phase, prompt, hero cell and depth before planning the next action.

## Release and validation

Release: CLI.6.1.0, protocol 6, audit schema 9, base game 3.3.8. The additional
public fields and restored content use the existing schema; earlier profiles are
neither migrated nor deleted.

The no-cache release gate completed on 2026-09-20: all 34 Gradle tasks executed,
with **533 Java tests passed**, zero failures/errors/skips (18 protocol, 330 game
control, 185 desktop control). Two historical assertions that expected lost
descriptions/empty nodes were replaced with strict retention checks before the
successful gate. New tests construct the native guess window and invoke the native
wand targeting callback without launching a personal profile. Source composition
checks report no unreviewed operations. The static UI inventory remains 1,910
records with zero unmapped routes; its eight baseline changes are reviewed source
line movements and the changed wand callback, not new runtime coverage claims.
