# UI 观察与操作意图版本

CLI 2.0 的意图签名使用安全来源 key、冻结参数和控制语义，排除英文模板与呈现诊断。资源查找或格式呈现波动不作为游戏输入；真实控件身份、选择内容、可用状态和输入代次仍参与版本判断。


完整 UI 观察用于理解当前画面内容，操作意图版本用于防止把旧操作施加到已经变化的上下文。这两个用途不能完全共用渲染对象的生命周期。例如，刚刚显示的伤害浮字在一秒后消失，会改变完整观察，却不会改变同一格攻击或移动的含义。

## 公开运行证据

本次只分析了以下测试输出目录中的 `strategy-public-*.ndjson` 和 `checkpoint-public.json`，没有读取该局存档或内部诊断数据库：

`desktop-control/build/playthroughs/20260909-030027-warrior-7df641a1/`

对每个 `STALE_STATE`，取请求引用版本的最近公开观察，与该拒绝后紧接着的成功 `state.get` 比较。所有 26 对观察的 `scope_id`、`phase`、UI 以外的全部公开字段和 UI 顶层元信息都相同。差异集中于 UI 子节点：

| 公开 trace 文件 | STALE 次数 | 仅浮字移除 | 仅 Attack Enemy enabled 变化 | 浮字与 enabled 同时变化 |
|---|---:|---:|---:|---:|
| `strategy-public-43b88fc2.ndjson` | 5 | 3 | 2 | 0 |
| `strategy-public-a5fad5fa.ndjson` | 13 | 11 | 1 | 1 |
| `strategy-public-af3660b4.ndjson` | 0 | 0 | 0 | 0 |

其中 `effa20ad` 的全部 8 次拒绝只涉及 `Guidebook`、`dodged`、`1`、`5` 等浮字节点移除，没有英雄、地图、背包、可见实体、按钮或血条变化。这里按实际对象类型识别浮字；不能按文字内容猜测一个数字或提示是否可忽略。

另外 4 次涉及 `Attack Enemy` 控件的 `enabled` 变化。源码中该指示器在背景隐藏后仍让 `active` 保留 0.75 秒，用于其显示/输入生命周期；当前公开 `enabled` 来自控件 `isActive()`。这类变化涉及控件可用性表达，需要单独审查。不能因为它们没有伴随英雄 HP 变化，就删掉所有 `enabled` 校验。

## 保守修正

`UiBridge.describeUi()` 和 `contextSignature()` 保留完整观察，包括浮字。另加只读的 `intentSignature()`：

- 只排除已经存在的 `FloatingText` 实例节点，保留普通文本、选项、按钮、输入框、滑块、菜单与血条。
- 保留控件引用身份、可用状态、文字/标签/值、选择器回调生命周期和当前场景/交互作用域。
- 保留血条像素数据；怪物的可见健康变化不能因为公开 DTO 没有真实 HP 字段而丢失校验。
- 查询不创建窗口、不调用操作回调，也不修改显示或游戏状态。

协调器接入时应组合：当前局/场景及阶段、UI 之外的公开核心状态、`intentSignature()`、真实 GUI 输入变更计数以及操作事务的版本变化。不能在采用新签名后又把原始 `observation.ui` 整体加入同一哈希，否则浮字到期仍会使版本变化。

真实 GUI 输入计数应在前置输入处理器可能消费事件之前递增，使零伤害攻击、没有净状态变化的点击、文本编辑等也能废弃旧意图。鼠标移动、悬停和纯渲染更新不应充当真实操作。该计数与核心状态比较互补，不能取代 HP、地图、库存、选择器和有效控件检查。

每次请求仍保存完整公开观察和内部审计快照。保持意图版本不变不意味着抹去两次观察之间的渲染差异。

## 未处理的长按

原生 `Button.update()` 在调用 `onLongClick()` 前就清空 `pressedButton`。即使回调返回 `false`，后续指针抬起也会清除 `clickReady`，键盘抬起也不会执行普通点击。因此完整长按的正确语义不是自动补一次点击。

CLI 对当前控件实际声明支持的长按调用原回调；回调返回 `false` 时，完成这次输入，不追加 `onClick()`，也不把正常无动作视为执行异常或 `EXECUTION_UNKNOWN`。未知手势及当前控件不存在的手势仍由只读验证拒绝。
